认识 STM32

P1 · P2 [1-1][1-2]

1. STM32 是什么

ST（意法半导体）公司基于 ARM Cortex-M 内核的 32 位微控制器。型号很多，按内核分 M0 / M3 / M4 / M7 等，F103 是 Cortex-M3 内核，72MHz 主频，属于性价比最高的入门系列。

2. 命名规则（读懂型号）

STM32F103C8T6
系列通用型增强型引脚数
C=48		Flash 容量
8=64KB		封装
T=LQFP		温度/版本

常见芯片对应：STM32F103C8T6（48脚/64KB，最小系统板）· STM32F103ZET6（144脚/512KB）· STM32F103RCT6（64脚/256KB）。

3. 芯片内部结构（框架图要会画）

  • 内核：Cortex-M3 CPU + 中断控制器 NVIC + 调试接口 SWD/JTAG + 系统定时器 SysTick
  • 存储：Flash（程序）+ SRAM（数据）
  • 总线：AHB（高速总线，接内核/存储/DMA）+ APB1/APB2（外设总线，时钟不同，APB2 更快）
  • 外设：GPIO、USART、SPI、I2C、TIM、ADC、DMA、RTC、看门狗……
记忆锚点GPIO、USART1、TIM1 等挂在 APB2（72MHz）；USART2/3、TIM2~4 等挂 APB1（36MHz）。外设时钟必须先开，这是后面每个外设初始化第一步。

4. 最小系统板（蓝板的构成）

  • 供电：3.3V / 5V / GND，USB 口或外部供电
  • 晶振：8MHz 外部晶振（HSE）+ 32.768kHz（RTC 用）
  • 复位：NRST 按键复位
  • 启动配置：BOOT0 / BOOT1 跳线（决定从 Flash / 系统存储器 / SRAM 启动）
  • 调试：SWD 接口（SWDIO=PA13、SWCLK=PA14）
  • 板载外设：LED（蓝板通常 PC13）、按键（KEY）、USB 转串口等

GPIO —— 最基础的外设

P5–P8 [3-1]~[3-4]

3-1 GPIO 输出（理论）· P5

GPIO = 通用输入输出口。F103 有 GPIOA~GPIOE（大容量还有 F/G），每组 16 个引脚（PIN0~PIN15）。引脚既可以输出高低电平，也可以读外部电平。

八种工作模式（重点记 4 种）

类别模式特点典型用途
输入上拉输入 IPU内部上拉，默认高电平按键（按下接地变低）
下拉输入 IPD内部下拉，默认低电平按键（按下接电源变高）
输出推挽输出 PP强驱动，输出 0/1 都有能力LED、蜂鸣器等普通 IO
开漏输出 OD只能拉低，拉高靠外部上拉I2C、电平转换
一句话驱动 LED 用 推挽输出（GPIO_Mode_Out_PP），读按键用 上拉输入（GPIO_Mode_IPU）。浮空输入/模拟输入先了解即可。

GPIO 输出库函数三板斧

// 1. 开时钟：任何外设使用前必须先开对应总线时钟
void Led_Init(void)
{
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);  // GPIOA 挂在 APB2

    // 2. 定义并填写结构体（三要素：引脚 / 模式 / 速度）
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_4;      // 引脚
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP; // 推挽输出
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz; // 翻转速度

    // 3. 初始化：把配置写进寄存器
    GPIO_Init(GPIOA, &GPIO_InitStructure);
}

// 输出电平三件套
GPIO_SetBits(GPIOA, GPIO_Pin_4);      // 置高 → 灯灭（常见接法）
GPIO_ResetBits(GPIOA, GPIO_Pin_4);    // 置低 → 灯亮
GPIO_WriteBit(GPIOA, GPIO_Pin_4, Bit_SET);  // 按位写，效果同上

3-2 LED 闪烁 · 流水灯 · 蜂鸣器（代码）· P6

LED 闪烁 = 电平翻转 + 延时

while(1)
{
    GPIO_ResetBits(GPIOA, GPIO_Pin_4);  // 亮
    Delay_ms(500);
    GPIO_SetBits(GPIOA, GPIO_Pin_4);    // 灭
    Delay_ms(500);
}

流水灯 = 移位 + 取反（点亮后循环右移）

unsigned char i;
while(1)
{
    for(i=0; i<8; i++)
    {
        GPIO_Write(GPIOA, ~(0x01 << i));  // 每次只有第 i 位为 0 → 对应灯亮
        Delay_ms(100);
    }
}

蜂鸣器 = 有源蜂鸣器，IO 给高电平就响

有源蜂鸣器内部自带振荡源，直接给高电平就响；无源的需要 PWM 方波驱动（后面 TIM 章节学）。初始化同样三要素，把引脚换成蜂鸣器那个脚即可。

核心套路一切 GPIO 输出的写法都是：开时钟 → 配结构体 → GPIO_Init → SetBits/ResetBits 控制。LED、蜂鸣器、继电器、数码管段码……全部同一套。

3-3 GPIO 输入 + 必备 C 知识（理论）· P7

按键输入原理

  • 按键一端接 GPIO（如 PB3），一端接 GND
  • GPIO 配置为 上拉输入：不按时读到高电平 1，按下接地读到低电平 0
  • 用 GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_3) 读取
void Key_Init(void)
{
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_3;
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;   // 上拉输入
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);
}

消抖（必考概念）

机械按键按下瞬间会有 10~20ms 的抖动，电平在 0/1 之间弹跳。软件方案：检测到低电平 → 延时 20ms → 再确认还是低 → 才算按下。

知识点在工程里的体现
宏定义 #define配置参数、引脚定义

指针GPIO_Init(GPIOA, &结构体) 传地址

记忆锚点库函数风格：GPIO_Init(GPIOx, &结构体) —— 第一个参数是外设基址（如 GPIOA），第二个是配置结构体指针。所有外设（USART/TIM/ADC…）初始化都是这个模式。

3-4 按键控制 LED · 光敏传感器（代码）· P8

按键扫描 = 消抖 + 松手检测（完整流程）

unsigned char Key_Read(void)
{
    unsigned char temp = 0x00;
    if(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_3) == 0)  // 检测到按下
    {
        Delay_ms(20);                                       // 消抖
        while(GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_3) == 0);  // 等待松手（防连按）
        Delay_ms(20);
        temp = 0x01;                                       // 返回按键编号
    }
    return temp;
}

main 里的用法：

while(1)
{
    if(Key_Read() == 0x01)  GPIO_ResetBits(GPIOA, GPIO_Pin_4);  // 按下 → 亮
    else                       GPIO_SetBits(GPIOA, GPIO_Pin_4);    // 松开 → 灭
}

光敏传感器控制蜂鸣器（同一套路换外设）

  • 光敏模块输出数字电平（光强超过阈值输出高/低，板上有比较器）
  • GPIO 配成输入，读到对应电平 → 开/关蜂鸣器
  • 和按键唯一的区别：按键按一下要"松手检测"，传感器是持续电平，直接读即可
本章总结输入输出都是同一流程：开时钟 → 配结构体（模式决定输入/输出）→ GPIO_Init。输入用 GPIO_ReadInputDataBit 读，输出用 GPIO_SetBits/ResetBits 写。这就是 GPIO 的全部。

OLED 显示屏 —— 调试利器

P9 · P10 [4-1][4-2]

1. 为什么先学 OLED（4-1 理论）

  • 前面调试只能靠 LED 亮灭，信息量太小
  • OLED 能实时显示数值/变量/波形，是嵌入式开发的"printf"
  • 后面的所有章节（编码器、ADC、串口…）都用 OLED 看结果

2. OLED 模块基础

  • 常见 0.96 寸，SSD1306 驱动芯片，128×64 像素，I2C 接口（SDA/SCL/电源/GND 四线）
  • 江科大例程接法：SDA→PB7、SCL→PB6（F103 硬件 I2C1 引脚，但这里用软件模拟）
  • 屏幕分 8 页（page0~7），每页 128 个字节，一字节对应一列 8 个像素（垂直方向 8 位）
  • 显示字符/汉字本质是查字模表：OLED_Font.h 里存点阵数据

核心驱动函数（记住这套 API 即可用）

函数作用
OLED_Init()初始化（上电时序 + 配置命令 + 清屏）
OLED_Clear()清屏
OLED_ShowChar(x, y, ch)显示单个字符（x=列1~16，y=行1~4）
OLED_ShowString(x, y, str)显示字符串
OLED_ShowNum(x, y, num, len)显示数字（补零对齐）
OLED_ShowSignedNum(x, y, num, len)显示有符号数
OLED_ShowHexNum(x, y, num, len)显示十六进制

3. 软件 I2C 通信要点（4-2 代码）

  • I2C 协议：起始条件 → 设备地址+读写位 → 应答 → 数据字节 → 停止条件
  • SSD1306 地址：0x78（7位地址 0x3C 左移 1 位），写指令/数据用不同控制字节
  • 软件模拟：GPIO 翻转手动产生时钟时序，慢但灵活、引脚随意
  • OLED 驱动是标准库工程里第一个"多文件复杂驱动"，直接复制使用即可，重点是会用 API
记忆锚点OLED = 前面 GPIO（输出）+ 软件 I2C 协议（时序）+ 查表（字模）。它本身不难，但把"外设驱动"的套路完整走了一遍——以后接任何模块（温湿度、陀螺仪、Flash…）都是这个模式：看时序图 → 写底层收发函数 → 封装应用函数。

EXTI 外部中断

P11 · P12 [5-1][5-2]

1. 中断系统基础（5-1 理论）

CPU 正在执行主程序时，外部/内部事件突然打断它，跳去执行一段中断服务函数，执行完再回来继续主程序。好处：不用 CPU 轮询等待，响应快、省电。

相关概念（面试常问）

概念含义
中断源触发中断的事件（如引脚边沿、定时器溢出）
NVIC嵌套向量中断控制器，管理所有中断的使能/优先级
EXTI外部中断/事件控制器，把引脚信号转成中断请求
抢占优先级高抢占可打断低抢占（Group 决定分组方式）
响应优先级同抢占下按响应排序，不可打断（仅排队）
中断服务函数ISR，名字固定（如 EXTI0_IRQHandler），写在启动文件里

NVIC 优先级分组（4 位分配抢占/响应）

分组抢占优先级响应优先级
Group 00 位（无）4 位
Group 11 位3 位
Group 22 位2 位
Group 33 位1 位
Group 44 位0 位（无）

例程常用 Group 2：抢占 0~3、响应 0~3。整工程只能调用一次分组配置。

2. EXTI 配置流程（标准套路）

void Encoder_Init(void)
{
    // ① 开 GPIO 时钟 + AFIO 时钟（EXTI 引脚映射必须！）
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB | RCC_APB2Periph_AFIO, ENABLE);

    // ② 配置 GPIO 为输入（上拉）
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0 | GPIO_Pin_1;
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    // ③ GPIO 引脚 → EXTI 线 映射（重映射功能，依赖 AFIO）
    GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource0);
    GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource1);

    // ④ 配置 EXTI 触发方式（下降沿/上升沿/双边沿）
    EXTI_InitTypeDef EXTI_InitStructure;
    EXTI_InitStructure.EXTI_Line    = EXTI_Line0 | EXTI_Line1;
    EXTI_InitStructure.EXTI_Mode    = EXTI_Mode_Interrupt;
    EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;
    EXTI_InitStructure.EXTI_LineCmd = ENABLE;
    EXTI_Init(&EXTI_InitStructure);

    // ⑤ 配置 NVIC：使能对应中断线 + 优先级
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    NVIC_InitTypeDef NVIC_InitStructure;
    NVIC_InitStructure.NVIC_IRQChannel = EXTI0_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_Init(&NVIC_InitStructure);
}

中断服务函数模板（写在哪个 .c 里都行，名字必须对）

void EXTI0_IRQHandler(void)
{
    if(EXTI_GetITStatus(EXTI_Line0) == SET)   // 判断是否本中断线触发
    {
        EXTI_ClearITPendingBit(EXTI_Line0);     // 清中断标志（必须！否则一直进）
        // ... 处理逻辑 ...
    }
}
铁律中断服务函数里一定要先判断标志、再清标志，否则会反复触发死循环。函数名必须是启动文件里注册的名字（EXTI0_IRQHandler 等），拼错则中断静默失效——编译器不报错，最阴的坑。

3. 两个实战例程（5-2 代码）

对射式红外传感器计次

  • 红外发射/接收对管：遮挡 → 输出电平变化 → EXTI 中断计数
  • 就是"光敏/按键的 GPIO 输入 + EXTI 中断"组合：电平变了进中断 +1

旋转编码器计次（正交编码器）

  • 编码器输出 A、B 两相（相差 90°），旋转方向由相位关系决定
  • 思路：A 相下降沿触发中断 → 在中断里读 B 相电平判断方向（B 高=正转，B 低=反转）
  • 中断里 encoder_count++ / --，main 里读显示
  • EXTI 中断方式读编码器在快速旋转时会丢脉冲，后面 6-7 用 TIM 编码器接口硬件正交解码才是正解

本章总结中断五步走：① 开时钟(GPIO+AFIO) → ② 配 GPIO → ③ GPIO_EXTILineConfig 映射 → ④ EXTI_Init 配触发 → ⑤ NVIC 使能+优先级。服务函数里先判标志、后清标志。EXTI 让 CPU 从"轮询等待"变成"事件驱动"，这是后面定时器/串口/DMA 所有中断的基础。

TIM 定时器

P13 · P14 [6-1][6-2]

1. 定时器是什么（6-1 理论）

  • 定时器 = 硬件计数器：内部时钟每过一个周期 CNT++，溢出时产生更新中断，让 CPU 定时做某事
  • 比软件 Delay 好：不占用 CPU（Delay 期间 CPU 死等，定时器期间 CPU 干别的）
  • F103 有：TIM1/TIM8（高级定时器）、TIM2~5（通用）、TIM6/7（基本）。我们学 TIM2~4

定时器组成框图（必会画）

时钟源 ──► 预分频器PSC ──► 计数器CNT ──► 自动重装值ARR ──► 更新事件/中断
(72MHz)   (分频后)     (加1/减1)   (溢出条件)
  • PSC 预分频器：把 72MHz 分频，降低计数频率 → 决定计数周期
  • CNT 计数器：每来一个脉冲 +1
  • ARR 自动重装载：CNT 数到 ARR 就溢出清零，产生更新中断
溢出时间公式（必背）溢出时间 = (ARR+1) × (PSC+1) / 72MHz。
例：ARR=10000-1、PSC=7200-1 → (10000 × 7200) / 72M = 1 秒。
常用套路：先定 PSC 让计数频率为 1MHz（PSC=71 → 1µs 一个脉冲），ARR 直接就是微秒数。

2. 定时中断配置流程（6-2 代码）

void Timer_Init(void)
{
    // ① 开时钟：TIM2 在 APB1 总线上（注意是 APB1！）
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);

    // ② 选择时钟源（内部 72MHz 时钟）
    TIM_InternalClockConfig(TIM2);

    // ③ 配置时基单元：分频 / 计数模式 / 重装值
    TIM_TimeBaseInitTypeDef TimeBaseInitStructure;
    TimeBaseInitStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TimeBaseInitStructure.TIM_CounterMode   = TIM_CounterMode_Up;   // 向上计数
    TimeBaseInitStructure.TIM_Period        = 10000 - 1;        // ARR：重装值
    TimeBaseInitStructure.TIM_Prescaler     = 7200 - 1;        // PSC：预分频
    TimeBaseInitStructure.TIM_RepetitionCounter = 0;             // 高级定时器用，通用填0
    TIM_TimeBaseInit(TIM2, &TimeBaseInitStructure);

    // ④ 清标志 + 使能更新中断（NVIC 需要）
    TIM_ClearFlag(TIM2, TIM_FLAG_Update);
    TIM_ITConfig(TIM2, TIM_IT_Update, ENABLE);

    // ⑤ NVIC 使能中断
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    NVIC_InitTypeDef NVIC_InitStructure;
    NVIC_InitStructure.NVIC_IRQChannel = TIM2_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_Init(&NVIC_InitStructure);

    // ⑥ 启动定时器！（忘了它定时器不跑）
    TIM_Cmd(TIM2, ENABLE);
}

// 中断服务函数：每秒 Num++
void TIM2_IRQHandler(void)
{
    if(TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)
    {
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);   // 先清标志
        Num++;
    }
}

3. 两个容易漏的坑（我踩过）

坑后果解法
时钟开错总线（TIM2 写成 APB2）寄存器写不进去，定时器不工作TIM2~4 用 RCC_APB1PeriphClockCmd；TIM1/8 才是 APB2
忘了 TIM_Cmd(TIM2, ENABLE)配置全对但定时器不跑初始化最后必须启动定时器
忘了 main 里调用 Timer_Init()Num 永远 0所有外设初始化都要在 main 里调用
本章总结定时器定时中断 = 开时钟(APB1) → 选时钟源 → 配 PSC/ARR → 使能更新中断 → NVIC → TIM_Cmd 启动。核心是记住溢出时间公式：溢出时间 = (ARR+1)×(PSC+1)/72MHz。TIM 是 F103 最复杂的外设，后面 PWM（输出比较）、输入捕获、编码器接口都是基于这个时基单元扩展的。

TIM 输出比较 —— PWM 驱动（呼吸灯/舵机）

P15 · P16 [6-3][6-4]

1. PWM 是什么（6-3 理论）

  • PWM（脉宽调制）：固定频率的方波，通过调节占空比（高电平时间占比）传递信息
  • 应用：LED 亮度（呼吸灯）、舵机角度、电机转速、蜂鸣器音调——本质都是"占空比控制"
  • 输出比较单元：CNT 与 CCR（比较寄存器）比较，CNT<CCR 输出高、CNT>=CCR 输出低 → 自动产生 PWM，全程不占 CPU
记忆锚点PWM 频率 = ARR 决定（1/周期），占空比 = CCR 决定（CCR/ARR）。改 CCR 就能连续调亮度/角度/转速。

2. PWM 配置（6-3 代码，呼吸灯）

// 复用推挽输出：把 TIM 通道信号引到 GPIO 引脚
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;    // ← 注意是复用推挽，不是普通推挽
GPIO_InitStructure.GPIO_Pin  = GPIO_Pin_1;          // PA1 = TIM2_CH2
GPIO_Init(GPIOA, &GPIO_InitStructure);

// 时基：ARR=100，PSC=720 → PWM 频率 = 72M/(720×100) = 1kHz
TIM_TimeBaseInit(TIM2, &TimeBaseInitStructure);

// 输出比较通道配置（核心四要素）
TIM_OCInitTypeDef OCInitStructure;
TIM_OCStructInit(&OCInitStructure);                 // 先填默认值，防遗漏字段
OCInitStructure.TIM_OCMode      = TIM_OCMode_PWM1;     // PWM 模式1：CNT<CCR 输出有效电平
OCInitStructure.TIM_OCPolarity  = TIM_OCPolarity_High; // 输出极性：高电平有效
OCInitStructure.TIM_OutputState = TIM_OutputState_Enable;
OCInitStructure.TIM_Pulse       = 0;                  // CCR 初始值
TIM_OC2Init(TIM2, &OCInitStructure);               // 通道2 → 对应 PA1

// 启动定时器
TIM_Cmd(TIM2, ENABLE);

// 运行时改占空比：i 从 0→100 循环 → 呼吸灯
PWM_SetCompare2(i);    // 内部就是 TIM_SetCompare2(TIM2, i)

3. 舵机驱动（6-4 代码）

  • 舵机（SG90 等）：20ms 周期 PWM，脉宽 0.5ms~2.5ms 对应 0°~180°
  • 配置：PSC=72-1（1MHz 计数）、ARR=20000-1（20ms 周期）→ CCR=500/1000/1500/2000 对应 0°~135°
  • 接线：红=5V、棕/黑=GND、橙/黄=信号线（接 PA1）
  • 舵机必须独立 5V 供电，GND 与板子共地——STLink 的 3.3V 带不动
// 舵机角度切换（配按键循环换档）
void Servo_control(unsigned char state)
{
    switch(state)
    {
        case 0: PWM_SetCompare2(500);   break;   // ≈0°
        case 1: PWM_SetCompare2(1000);  break;   // ≈45°
        case 2: PWM_SetCompare2(1500);  break;   // ≈90°
        case 3: PWM_SetCompare2(2000);  break;   // ≈135°
        default: break;
    }
}
switch 铁律每个 case 必须 break！漏了会"穿透"（fall-through），state=0 时会一路执行到 case 3，舵机永远停在最后的角度——这是我踩过的坑。
本章总结PWM 输出比较四要素：① GPIO 复用推挽 → ② 时基（PSC/ARR 定频率）→ ③ OC 配置（模式/极性/通道）→ ④ 改 CCR 定占空比。一个 PWM 外设能驱动 LED/舵机/电机/蜂鸣器，是嵌入式控制的核心基本功。

TIM 输入捕获 —— 测频率与占空比

P17 · P18 [6-5][6-6]

1. 输入捕获原理（6-5 理论）

  • 外部方波信号从 TIMx_CHy 引脚进入，引脚边沿触发时把当前 CNT 值"拍照"存进 CCR（捕获）
  • 相邻两次捕获的 CNT 差值 = 信号周期 → 频率 = 时钟/差值
  • 配合从模式（Reset）：捕获到上升沿自动清零 CNT，硬件自动连续测周期，CPU 只读结果
记忆锚点输出比较是"定时器往引脚输出"，输入捕获是"引脚往定时器输入"。测频率公式：Freq = 计数频率 / CCR1（CCR1 = 一个周期内的计数个数）。

2. 输入捕获配置（6-6 代码）

void IC_Init(void)
{
    // ① 引脚：PA6 = TIM3_CH1，配成输入（浮空/上拉均可）
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin  = GPIO_Pin_6;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    // ② 时基：PSC=71（1MHz 计数）、ARR 拉满防溢出
    TIM_TimeBaseInit(TIM3, &TimeBaseInitStructure);

    // ③ 输入捕获配置：通道1、上升沿、直连
    TIM_ICInitTypeDef ICInitStructure;
    ICInitStructure.TIM_Channel       = TIM_Channel_1;
    ICInitStructure.TIM_ICFilter      = 0xF;                // 滤波抗抖动
    ICInitStructure.TIM_ICPolarity    = TIM_ICPolarity_Rising;
    ICInitStructure.TIM_ICPrescaler   = TIM_ICPSC_DIV1;
    ICInitStructure.TIM_ICSelection   = TIM_ICSelection_DirectTI;
    TIM_PWMIConfig(TIM3, &ICInitStructure);   // PWM输入模式：自动配好两路捕获

    // ④ 从模式：TI1 上升沿触发 → 自动清零 CNT（测周期）
    TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1);
    TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset);

    TIM_Cmd(TIM3, ENABLE);
}

// ⑤ 读结果（main 里轮询显示）
uint32_t IC_GetFreq(void)
{
    return 1000000 / TIM_GetCapture1(TIM3);   // 1MHz ÷ 周期计数 = 频率(Hz)
}
uint32_t IC_GetDuty(void)
{
    return (TIM_GetCapture2(TIM3)+1) * 100 / (TIM_GetCapture1(TIM3)+1);  // 占空比%
}

3. 测试方案（PWM 自产自测）

  • 用一个 TIM 的 PWM 输出（如 PA0/PA1）当信号源，接到输入捕获引脚（PA6）
  • 调 PWM 预分频改变频率，OLED 上实时看测出的频率/占空比是否一致
  • 这验证了"输出比较 + 输入捕获"的闭环，也为后面 DMA、ADC 打了基础
本章总结输入捕获 = 引脚边沿 → 存 CNT → 差值算周期 → 从模式自动清零。测频率用 CCR1，测占空比再开一路捕获（PWMI 模式）。这是"定时器测量外设"的入口，面试常问"如何测频率"就答这套。

TIM 编码器接口 —— 硬件正交解码

P19 · P20 [6-7][6-8]

1. 为什么用硬件解码（6-7 理论）

  • 旋转编码器输出 A、B 两相（相位差 90°），转动方向和相位关系一一对应
  • 之前 5-2 用 EXTI 软件方案：A 相中断里读 B 相判方向 → 快速旋转会丢脉冲、还占 CPU
  • TIM 编码器接口：硬件同时监视 A/B 两相，自动判断方向并加减计数，CPU 只读 CNT，不丢脉冲
记忆锚点编码器接口 = 输入捕获 × 2（A、B 两路）+ 硬件判向计数。CNT 就是位置计数器，正转加、反转减，方向由硬件自动判断。

2. 编码器接口配置（6-8 代码）

void Encoder_Init(void)
{
    // ① 引脚：PA6=CH1、PA7=CH2，上拉输入（编码器信号默认高）
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin  = GPIO_Pin_6 | GPIO_Pin_7;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    // ② 时基：ARR 拉满（65535）、PSC=0（不分频），让 CNT 尽量大范围
    TIM_TimeBaseInit(TIM3, &TimeBaseInitStructure);

    // ③ 两路输入捕获（A→CH1、B→CH2），滤波防抖
    TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;   // 滤波 0xF
    TIM_ICInit(TIM3, &TIM_ICInitStructure);
    TIM_ICInitStructure.TIM_Channel = TIM_Channel_2;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    // ④ 编码器接口：TI1+TI2 双沿都计数（4 倍频）
    TIM_EncoderInterfaceConfig(TIM3, TIM_EncoderMode_TI12,
                               TIM_ICPolarity_Rising, TIM_ICPolarity_Rising);
    TIM_Cmd(TIM3, ENABLE);
}

// ⑤ 读位置并清零（周期采样）
int16_t Encoder_Get(void)
{
    int16_t Temp = TIM_GetCounter(TIM3);
    TIM_SetCounter(TIM3, 0);   // 读后清零，下次从 0 开始计
    return Temp;                 // 返回本次转动量（带符号）
}

3. 对比记忆：软件 vs 硬件方案

方案实现优点缺点
EXTI 软件（5-2）中断里读另一相判向简单、引脚灵活快速旋转丢脉冲、占 CPU
TIM 编码器接口（6-8）硬件正交解码计数不丢脉冲、不占 CPU只能用特定引脚（CH1/CH2）
本章总结编码器接口 = 双通道输入捕获 + 硬件判向 + CNT 加减计数。读 CNT 前先清零得到"本次转动量"。至此 TIM 四大功能全部学完：定时中断（时基）、输出比较（PWM）、输入捕获（测频）、编码器接口（正交解码）——它们共用同一个时基单元，只是"捕获/比较通道"的用法不同。

实战踩坑记录（亲身经历）

调试经验
⚠️
ST-Link 提示 "No target connected"
ST-Link 驱动正常但读不到芯片 → 先查接线：SWDIO→PA13、SWCLK→PA14、GND→GND，板子要单独供电。Settings 里 Clock Selected: 0 MHz 就是没通信上。
我这次的坑：杜邦线接错了引脚，换对后立刻识别。
⚠️
PB3 / PB4 按键失灵
F103 里 PA15、PB3、PB4 默认被 JTAG 占用，不能当普通 GPIO 用！按键若用 PB3/PB4，必须在初始化前关闭 JTAG：
RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE);
GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE);
只关 JTAG 不影响 SWD 下载。症状：按键按了没反应，甚至程序卡死。
⚠️
编译报 cannot open source input file "Led.c"
文件删了/没放进工程目录，但工程树里还挂着引用。规律：磁盘要有文件 + 工程树要添加 + 头文件路径要配，三步缺一不可。
⚠️
旋转编码器不管用 / 计数一直为 0
我踩过的双重坑：① main 里忘了调 Encoder_Init()，EXTI/NVIC 全没配置；② GPIO_EXTILineConfig 映射没开 AFIO 时钟（RCC_APB2PeriphClockCmd(..., RCC_APB2Periph_AFIO, ENABLE)）。两个都是"中断静默失效"的典型，编译不报错、程序不崩溃，就是没反应。
规律：凡是用了 GPIO_EXTILineConfig / 引脚重映射，必须开 AFIO 时钟。
⚠️
舵机工程按键没反应，排查半天竟是面包板虚接
症状：按键按下，探测引脚电平纹丝不动（IPU 下一直 1、IPD 下一直 0）→ 说明按键根本没把引脚拉低/拉高。
软件配置来回改了 N 轮（IPD/IPU 都试过）都是对的，最后发现是面包板接触不良，换跳线后立刻正常。
教训：探测值固定不变时，先用跳线短接引脚测硬件，别继续改软件。面包板虚接是嵌入式调试的头号隐藏刺客。
⚠️
Servo.h 拼写错误（Sevro.h）+ switch 缺 break
① 头文件 Sevro.h 写反字母，代码 include Servo.h → 编译报 cannot open；
② Servo.c 的 switch 每个 case 漏 break → fall-through 穿透，state=0 会一路执行到最后一个 case，舵机永远停在最后角度。
两个都是"症状与代码分离"的坑：编译错找文件，行为错找逻辑。
