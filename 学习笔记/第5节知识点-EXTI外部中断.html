中断是什么（一句话建立直觉）

中断 = CPU 干活干得好好的，被一个紧急事件"打断"，先去处理紧急事，处理完回来接着干。

类比你在写作业（主程序），妈妈喊你"来吃饭"（中断请求）——你先保存当前写到哪一页（保护现场），去吃饭（执行中断服务函数），吃完回来接着写（恢复现场）。
好处：不用每写一行就问"该吃饭了吗"（轮询），妈妈一喊你就知道（事件驱动）——CPU 更高效。

轮询 vs 中断：

方式做法缺点
轮询（无中断）while 循环里反复检查按键状态CPU 一直"空转检查"，浪费；响应慢
中断（事件驱动）按键触发 EXTI → 自动跳去处理CPU 平时干别的，来了才处理，高效
一句话你的 1004 红外计次、1005 编码器，都是 EXTI 中断——平时 CPU 刷新 OLED，红外被挡一下才跳进去 +1。

图 2 · EXTI 基本结构（PPT 第 47 页）—— 外部信号怎么变成中断

👆 点击图中色块高亮。这张图回答：GPIO 引脚上的电平变化，是怎么一路走到 NVIC 的？

EXTI = 「门卫」：GPIO 的 16 根线经 AFIO 选通，EXTI 检测到边沿就向 NVIC 报"有人来了"

两图连起来看（怎么讲清楚"中断从哪来到哪去"）

  1. 源头：按键/红外/编码器 → GPIO 引脚电平变化（PPT 47 页左侧 GPIOA~C）
  2. 选路：AFIO 决定"这根引脚对应哪条 EXTI 线"（17 页右侧图里的 AFIO 中断引脚选择）——这就是 GPIO_EXTILineConfig 的硬件本质
  3. 检测：EXTI 边沿检测器看"是上升沿还是下降沿"，匹配就产生中断请求（EXTI0~15）
  4. 调度：请求进 NVIC（PPT 44 页），按优先级排队，最高者获胜（数字小优先）
  5. 执行：NVIC 通知 CPU → 保护现场 → 跳 ISR → 恢复现场
一句话记忆GPIO 是"门口"，AFIO 是"门卫选人"，EXTI 是"报警器"，NVIC 是"调度台"，CPU 是"干活的人"。你写的配置代码（GPIO_EXTILineConfig / EXTI_Init / NVIC_Init）就是在分别设置这四层。

NVIC 优先级：抢占 vs 响应（点卡片理解区别）

两个中断同时/先后到达时，谁先执行？看 抢占优先级 和 响应优先级 两个维度：

中断 A
抢占 1 · 响应 1
EXTI 红外计次（按键）
空闲
中断 B
抢占 0 · 响应 0
TIM2 定时中断（1 秒计时）
空闲
点击上方两个中断，看谁先执行
概念含义类比
抢占优先级高抢占可以打断正在执行的低抢占中断急诊插队，等级高的随时插
响应优先级抢占相同才比较；不可打断，只决定排队顺序同等级排队，先来先办
记忆抢占 = 能插队（打断）；响应 = 只能排队（不打断）。抢占等级小的数字=更高优先级？不！数字越小优先级越高（0 最高）。

旋转编码器判向原理（转一转就看懂 A/B 相位）

编码器输出 A、B 两相（相位差 90°）。正转/反转时，A、B 波形的先后顺序相反——CPU 靠"谁先跳变"判断方向：

计数 = 0
看懂了什么正转：A 上升沿时 B 是 低 → 计数 +1；反转：A 上升沿时 B 是 高 → 计数 -1。
你的 1005 编码器工程 EXTI0 中断里读 PB1（B 相）判方向——就是这个原理。
EXTI 方案的局限快速旋转时中断可能丢脉冲（中断还没处理完下一个沿就来了）。后面 6-8 用 TIM 编码器接口硬件正交解码，不丢脉冲。
4
EXTI 配置五步（点击展开，对照你的 1004 工程）
1
开时钟：GPIOB + AFIO
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB | RCC_APB2Periph_AFIO, ENABLE);
AFIO 时钟必开！GPIO_EXTILineConfig 引脚映射属于重映射功能。忘了它 → 中断静默失效（你 1005 踩过的坑）。
2
配置 GPIO 输入（上拉）
GPIO_Mode_IPU，引脚如 PB14（你的红外传感器）。传感器输出低电平触发。
3
引脚映射到 EXTI：GPIO_EXTILineConfig
GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource14);
把 PB14 接到 EXTI_Line14。这条线从哪来？只能从 GPIO 进来——16 个 EXTI 线对应 16 个引脚号，但每个引脚号只能选一组 GPIO。
4
配置 EXTI：触发方式（下降沿）
EXTI_Trigger_Falling = 下降沿触发（信号从高变低的瞬间触发一次）。红外被挡 → 输出从高变低 → 触发中断。
5
NVIC 使能中断线 + 优先级
NVIC_IRQChannel = EXTI15_10_IRQn（EXTI 线 10~15 共用这一个中断号！）
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2) —— 全工程只能调一次分组。
记忆口诀开时钟(AFIO) → 配 GPIO → 映射 EXTI → 配触发 → NVIC 使能。五步缺一不可。
5
中断服务函数模板（你的 1004 实际代码）
void EXTI15_10_IRQHandler(void)
{
    if(EXTI_GetITStatus(EXTI_Line14) == SET)  // ① 判断标志
    {
        EXTI_ClearITPendingBit(EXTI_Line14);  // ② 清标志（必须！）
        Counter_Sensor_Count++;                 // ③ 处理逻辑
    }
}
铁律（面试必问）① 先判断标志（多个中断线共用一个 Handler 时区分谁触发的）；② 必须清标志（不清 → 一直触发 → 死循环）；③ 函数名必须是启动文件注册的名字（EXTI0_IRQHandler / EXTI15_10_IRQHandler…），拼错 → 中断静默失效，编译器不报错。

实战坑（EXTI 特供）
① 忘了开 AFIO 时钟GPIO_EXTILineConfig 写不进 → 中断永不触发。症状：编译 0 错误，程序正常跑，就是没反应——最阴的坑，你 1005 踩过。
② 中断函数名拼错EXTI15_10_IRQHandler 拼成别的 → 中断静默失效，编译器不报错。查启动文件里的名字对照。
③ 忘了清标志EXTI_ClearITPendingBit 漏了 → 中断标志一直 SET → 反复进入 ISR → 主程序卡死。
④ NVIC 分组全工程只调一次NVIC_PriorityGroupConfig 重复调用可能导致优先级配置混乱。放在 main 最前面或某个 Init 里一次即可。
