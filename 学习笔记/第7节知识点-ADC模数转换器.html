① GPIO 模拟输入：18 路可选 1 路 ▶

STM32F103 的 ADC 一共支持 18 个输入通道：16 个外部 GPIO（IN0~IN15）+ 2 个内部（温度传感器 + VREFINT）。

GPIO 配模式：必须用 GPIO_Mode_AIN（模拟输入）—— 关掉施密特触发器与上拉下拉，避免干扰模拟信号。

记住ADC 用哪个脚，就把这个脚的 GPIO 配成 AIN。我们工程 1013/AD.c 用了 PA0~PA3（对应 ADC1 的通道 0~3）。
② 规则组 & 注入组：两套独立的"通道清单" ▶

通道选择器把 18 路模拟信号挑出 1 路送给 AD 转换器。但 18 选 1 一次只能转一路，怎么办？

  • 规则组：最多 16 个通道组成一个序列，可按顺序自动循环转换
  • 注入组：最多 4 个通道，可以"插队"打断规则组优先转换

数据寄存器：

  • 规则组只有 1 个 16 位数据寄存器 → 多个通道时会覆盖（后转的会盖掉前转的）！必须配合 DMA 把数据搬走
  • 注入组有 4 个 16 位数据寄存器 → 4 通道内不会覆盖
面试常问规则组多通道扫描，必须开 DMA，否则旧数据被新数据盖掉！我们初学先用单通道，不开 DMA 也行；多通道时一定记得。
③ AD 转换器：逐次逼近，把电压变成 12 位数字 ▶

核心模块：12 位逐次逼近型 ADC。它把 0~3.3V 的电压映射为 0~4095 的数字：

公式Value = VIN / 3.3V × 4095（对应关系 0~3.3V → 0~4095，线性）

逐次逼近原理（下一个 tab「逐次逼近原理」用动画演示）：

  1. 从最高位开始，试探这一位是 1 还是 0
  2. 用内部 DAC 输出对应电压，与输入电压比较
  3. 比较器决定这一位保留 1 还是清 0，锁存到 SAR
  4. 下一位重复 12 次，得到 12 位结果

时钟 ADCCLK：来自 RCC 的 ADCCLK 分频，最大 14MHz。72MHz / 6 = 12MHz（工程 1013 用的）。

④ EOC 与中断输出控制：转换完成怎么知道？ ▶

转换完成后 AD 转换器会置位 EOC（End Of Conversion） 标志。

  • 查询法：循环读 ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC)，等它变 SET（我们工程用的）
  • 中断法：开 ADC_ITConfig(ADC1, ADC_IT_EOC, ENABLE) + NVIC，转换完进中断服务函数（DMA 场景常用）
  • 模拟看门狗：值越界才中断（设阈值高/低，模拟看门狗自动比）
三道闸门类比 TIM：EOC 标志（CR 寄存器）+ EOCIE 使能（DIER）+ NVIC 通道（ADC1_2_IRQn）。缺一个中断不来。
⑤ 触发控制 & RCC & 开关控制：让 ADC 跑起来的三件套 ▶

想让 ADC 真正工作，需要：

  • 触发控制：给一个 START 信号，告诉 ADC「开始转换」。来源有两种：软件触发 或 硬件触发
  • RCC：开 ADC 时钟 + RCC_ADCCLKConfig(分频) 给 ADCCLK（最大 14MHz）
  • 开关控制：ADC_Cmd(ADC1, ENABLE) 把 ADON 位置 1，ADC 才通电
第一大坑代码全对但 AD 转换器不工作？检查：① ADCCLK ≤ 14MHz（72/6=12MHz OK） ② ADC_Cmd 开了 ③ 触发了（软件或硬件）。
逐次逼近原理（PPT 87 页 ADC0809 类比 + 交互演示） ▶

类比：PPT 87 页是 8 位 ADC0809 的内部结构，STM32F103 是 12 位逐次逼近，原理一模一样。

  • 8/12 个 SAR（逐次逼近寄存器）位
  • 一个内部 DAC（产生试探电压）
  • 一个比较器：DAC 电压 > 输入电压 → 该位清 0；反之置 1
  • 从最高位开始 8/12 轮试探 → 锁存最终结果

4 种转换模式（PPT 91-94 · 卡片切换） ▶

点击下方任一模式卡片，查看该模式下的信号流程与配置。

① 单次转换·非扫描 最常用

触发 1 次 → 转 1 通道 → 完成后 EOC=1 → 自动停止。
工程 1013 用的就是这种（虽然开了连续，但每次重新启动 = 单次效果）

② 连续转换·非扫描

触发 1 次 → 连续不停转同一通道，EOC 每转完置 1 次，CPU/DMA 持续读。

③ 单次转换·扫描

触发 1 次 → 按规则组序列（如 7 通道）依次转一遍 → EOC。必须配 DMA。

④ 连续转换·扫描

触发 1 次 → 7 通道依次转 → 循环不停。必须配 DMA。多通道实时监测。

① 单次转换·非扫描

代码对应：ADC_SoftwareStartConvCmd(ADC1,ENABLE) + while(ADC_GetFlagStatus(ADC1,ADC_FLAG_EOC)==RESET);

void AD_Init(void)
{
    // ① 开时钟：ADC1 + GPIOA（都在 APB2）
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_ADC1, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
    RCC_ADCCLKConfig(RCC_PCLK2_Div6);   // ADCCLK = 72/6 = 12MHz（<=14MHz）

    // ② GPIO 配模拟输入（PA0~PA3 → 通道 0~3）
    GPIO_InitTypeDef GPIO_Init_Structure;
    GPIO_Init_Structure.GPIO_Mode = GPIO_Mode_AIN;
    GPIO_Init_Structure.GPIO_Pin  = GPIO_Pin_0 | GPIO_Pin_1 | GPIO_Pin_2 | GPIO_Pin_3;
    GPIO_Init(GPIOA, &GPIO_Init_Structure);

    // ③ ADC_Init（核心：模式/对齐/触发/通道数）
    ADC_InitTypeDef ADC_Init_Structure;
    ADC_Init_Structure.ADC_ScanConvMode     = DISABLE;   // 非扫描
    ADC_Init_Structure.ADC_ContinuousConvMode = ENABLE;  // 连续
    ADC_Init_Structure.ADC_DataAlign        = ADC_DataAlign_Right;
    ADC_Init_Structure.ADC_ExternalTrigConv = ADC_ExternalTrigConv_None; // 软件触发
    ADC_Init_Structure.ADC_Mode             = ADC_Mode_Independent;
    ADC_Init_Structure.ADC_NbrOfChannel     = 1;
    ADC_Init(ADC1, &ADC_Init_Structure);

    // ④ 上电 + 校准（开关控制）
    ADC_Cmd(ADC1, ENABLE);                  // ADON = 1
    ADC_ResetCalibration(ADC1);             // 复位校准
    while(ADC_GetResetCalibrationStatus(ADC1) == SET);
    ADC_StartCalibration(ADC1);             // 开始校准
    while(ADC_GetCalibrationStatus(ADC1) == SET);
}

// ⑤ 单次启动 + 等 EOC + 读值（对应触发/EOC/数据寄存器）
uint16_t AD_GetValue(uint8_t ADC_Channel)
{
    ADC_RegularChannelConfig(ADC1, ADC_Channel, 1, ADC_SampleTime_55Cycles5);
    ADC_SoftwareStartConvCmd(ADC1, ENABLE);            // 软件触发 START
    while(ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET); // 等 EOC=1
    return ADC_GetConversionValue(ADC1);                  // 读规则组数据寄存器
}
对应关系① RCC → ② GPIO_AIN → ③ ADC_Init → ④ ADC_Cmd + 校准 → ⑤ RegularChannelConfig + SoftwareStartConv + 等 EOC + 读值 —— 正好沿 89 页结构图从左到右、从上到下走一遍。
触发与对齐（PPT 95-96） ▶

触发控制

ADC 启动转换需要一个 START 触发信号。两种来源：

触发方式配置代码典型场景
软件触发ADC_ExternalTrigConv_NoneADC_SoftwareStartConvCmd(ADC1,ENABLE)单次采样、查询法
（工程 1013）
硬件触发（定时器）ADC_ExternalTrigConv_Tx_TRGO配置 TIM 产生 TRGO定时采样、DMA 配合
硬件触发（EXTI）ADC_ExternalTrigConv_Ext_IT11配置外部中断外部信号同步采样
记住我们初学全用 软件触发（最简单），硬件触发是进阶玩法。

数据对齐（PPT 96）

ADC 是 12 位，但数据寄存器是 16 位。12 位数据放哪 4 位空着，就有两种对齐方式：

假设 12 位转换结果 = 0xABC（二进制 1010 1011 1100）
右对齐（常用）
左对齐
右对齐读出来的值 = 0x0ABC = 2748，电压 = 2748/4095×3.3V ≈ 2.21V
结论我们用 右对齐，读出来直接就是 0~4095 的真实值；左对齐 = 右对齐 × 16（左移 4 位），常配合 8 位精度 场景。
时间与校准（PPT 97-98） ▶

转换时间公式

公式（PPT 97）TCONV = 采样时间 + 12.5 个 ADC 周期

采样时间可配：1.5 / 7.5 / 13.5 / 28.5 / 41.5 / 55.5 / 71.5 / 239.5 周期（ADC_SampleTime_xxxCycles5 系列）。采样时间越长越准，但越慢。

校准（PPT 98）

ADC 内部有电容阵列，会引入误差。STM32 内置自校准，算一个误差修正码，转换时自动消除。

// 建议每次上电后跑一次（标准库范例）
ADC_ResetCalibration(ADC1);
while(ADC_GetResetCalibrationStatus(ADC1) == SET);
ADC_StartCalibration(ADC1);
while(ADC_GetCalibrationStatus(ADC1) == SET);
注意校准前 ADC 必须断电至少 2 个 ADC 时钟周期。我们 ADC_Cmd(ENABLE) 后立刻 ResetCalibration —— 满足要求。
其他要点 分辨率、电压、坑 ▶

分辨率 & 电压（PPT 86）

  • 分辨率：12 位 = 2¹² = 4096 级
  • 输入电压范围：0~3.3V（VSSA = GND，VDDA = 3.3V）
  • 转换结果范围：0~4095
  • 量化单位：3.3V / 4095 ≈ 0.81mV（最低有效位）

3 个坑

坑症状正解
ADCCLK 超过 14MHz转换结果异常 / ADC 不工作RCC_ADCCLKConfig 选 ≤ 6 分频（72/6=12MHz）
GPIO 配成普通输入或上拉测出的值受上下拉影响、不准配 GPIO_Mode_AIN
多通道扫描没开 DMA数据被覆盖、读不准扫描模式必须配 DMA

模拟看门狗（AWD）

设两个阈值（高/低，12 位），当转换结果越界时自动触发 AWD 中断，可用来监测电压异常（如电池过放）。配置：ADC_AnalogWatchdogThresholdsConfig + ADC_AnalogWatchdogSingleChannelConfig。

面试一句话 / 标准答法

  • ADC 是什么：把模拟电压转成 12 位数字量，建立模拟电路到数字电路的桥梁。
  • 工作原理：逐次逼近（二分法思想，12 步锁存 12 位结果）。
  • F103C8T6 ADC 资源：2 个 ADC（ADC1/2），10 个外部通道，最多 18 路；分辨率 12 位，最大 ADCCLK 14MHz。
  • 规则组 vs 注入组：规则组最多 16 通道只有 1 个数据寄存器，多通道必须配 DMA；注入组最多 4 通道有 4 个数据寄存器，不会覆盖。
  • 计算电压：V = Value × 3.3V / 4095（右对齐）。
  • ADCCLK 限制：最大 14MHz（72MHz / 6 = 12MHz 常用）。
