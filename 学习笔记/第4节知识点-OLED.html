OLED 是什么（为什么它叫"调试利器"）

OLED（有机发光二极管显示屏）——你能在板子上"看见"程序在干什么。一句话：没有它，你只能靠 LED 亮灭猜程序状态；有了它，任何变量/数值直接显示在屏幕上。

  • 常见 0.96 寸，SSD1306 驱动芯片，128×64 像素，I2C 接口（SDA/SCL/电源/GND 四线）
  • 江科大例程接法：SCL→PB8、SDA→PB9（你的工程就是这么接的）
  • 后面所有章节（编码器、ADC、串口…）都靠 OLED 看结果——它是你的"眼睛"
记忆锚点OLED = 显示字符串 + 显示数字 + 显示十六进制 + 显示波形。核心就一个"查字模表"的原理：每个字符 → 一串点阵数据 → 屏幕上点亮对应像素。

3
软件 I2C 时序（一步步看数据怎么发出去）

I2C = 两根线：SCL（时钟，谁说话谁管节奏）+ SDA（数据，双向）。软件模拟 = 用 GPIO 翻转手动"画"出协议时序，不依赖硬件外设。

（点击播放/单步，看 SCL/SDA 每一步的状态）
步骤SCLSDA含义
起始条件 START高高→低（SCL 高时 SDA 下降沿）告诉所有设备"我要开始通信了"
设备地址8 个脉冲0x78 = 0111 1000（7位地址 0x3C + 写位0）点名要跟谁说话
应答 ACK第 9 个脉冲从机拉低OLED 回答"我在"
控制字节8 脉冲0x00（命令）或 0x40（数据）告诉 OLED"下面发的是命令还是数据"
数据字节每个 8 脉冲字模数据真正的内容
停止条件 STOP高低→高（SCL 高时 SDA 上升沿）"我说完了"
面试常问为什么 OLED 驱动"直接复制就能用"？因为它本质就是 GPIO 输出 + 时序——你在第 3 节学的推挽输出，在这里被用来"画"协议波形。底层还是 GPIO！

API 速查表（用起来就这几句）
函数作用示例
OLED_Init()初始化（上电时序+配置命令+清屏）main 开头调用一次
OLED_Clear()清屏刷新前调用
OLED_ShowChar(x, y, ch)显示单个字符x=1~16 列，y=1~4 行
OLED_ShowString(x, y, str)显示字符串OLED_ShowString(1,1,"Hello")
OLED_ShowNum(x, y, num, len)显示数字（补零对齐）OLED_ShowNum(1,7,1234,4) → "1234"
OLED_ShowSignedNum(x, y, num, len)显示有符号数编码器计数（可正可负）
OLED_ShowHexNum(x, y, num, len)显示十六进制寄存器值
坐标规则OLED 4 行 × 16 列（每字符 8×8 像素，128/8=16 列，64/8=8 行但驱动封装成 4 行大字）。x=列、y=行，写错了字会跑到别的位置。
本项目用法你 1006 工程里 OLED_ShowNum(1,1,Num,4) 每秒刷新定时器计数——这就是"OLED 看结果"的标准姿势：主循环里不断刷新显示。
5
软件 I2C vs 硬件 I2C
软件 I2C（江科大例程）硬件 I2C（F103 外设）
原理GPIO 翻转手动产生时序I2C 外设自动产生时序
引脚任意 GPIO（PB8/PB9）固定引脚（I2C1=PB6/PB7 或重映射）
速度慢（软件模拟）快（硬件）
复杂度代码直观、好调试库函数少但出问题难查
选谁入门/教学首选高速大量传输时用
坑F103 硬件 I2C 有"兼容性不佳"的传说（卡死问题），所以江科大教程直接教软件 I2C——稳定、易懂、引脚随便。你的 OLED 就是软件 I2C。
!
实战坑
① 显示乱码/花屏多半是字模表 OLED_Font.h 没加进工程，或引脚接反（SDA/SCL 对调）。先查接线，再查文件。
② 坐标超界OLED_ShowString(20,1,...) 第 20 列超出了 16 列范围 → 显示错乱。列范围 1~16，行范围 1~4。
③ 忘了 OLED_Initmain 里没调 OLED_Init()，屏幕全黑。所有外设都要先 Init 再用——第 3 节的老规矩。
