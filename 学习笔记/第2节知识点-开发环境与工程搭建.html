2
新建工程七步（点击步骤展开细节 · 用"下一步"逐步走）
1
New Project → 选芯片 STM32F103C8
告诉 Keil 目标芯片型号。选对芯片后 Keil 才知道：
• 有哪些外设寄存器可访问
• 用什么启动文件（md/hd）
• 内存布局（Flash/SRAM 大小）
STM32F103C8 = 48脚 / 64KB Flash / 中容量
2
添加启动文件 startup_stm32f10x_md.s
芯片上电后执行的第一段汇编代码：
• 建立中断向量表（复位/中断 → 处理函数地址表）
• 初始化堆栈指针 SP
• 调用 SystemInit() 配时钟 → 跳转 main()
md = Medium Density（中容量，64~128KB Flash 的芯片用）
选错启动文件 = 上电就跑飞
3
添加固件库源码（core_cm3.c + system_stm32f10x.c + 外设 .c）
• core_cm3.c：Cortex-M3 内核函数（NVIC/SysTick 操作）
• system_stm32f10x.c：系统时钟初始化（72MHz 配置）
• stm32f10x_gpio.c 等：各外设库函数实现
用什么外设就加什么 .c（全加也行，就是编译慢点）
4
添加用户代码 main.c
你写的程序入口。Keil 会把它和库一起编译链接，生成最终固件 .hex/.axf。
main.c 本质：调用各外设的 Init → while(1) 主循环。
新手常见坑：只建了文件忘了加进工程树，编译报 "Led.c not found"
5
配置宏定义 USE_STDPERIPH_DRIVER、STM32F10X_MD
两个宏是"开关"：
• USE_STDPERIPH_DRIVER → 启用标准外设库（没有它，stm32f10x.h 里函数声明全没有）
• STM32F10X_MD → 声明芯片是中容量（影响 Flash 分页大小等配置）
换芯片必须改第二个宏：LD（低容量）/ MD（中）/ HD（高）/ XL（超大）
6
配置头文件路径 Include Paths
编译器找 #include "xxx.h" 时的搜索目录清单：
.\Start; .\Library; .\System; .\Driver; .\User
少配一个目录 → 报 cannot open source input file
新增模块文件夹（如 Driver）时，记得把路径加进来
7
配置调试器：ST-Link + Port 选 SW
告诉 Keil 用什么工具把固件烧进芯片：
• Debug → ST-Link Debugger
• Settings → Port 选 SW（不是 JTAG，省引脚）
• Reset 选 HW RESET 或 Connect under Reset（部分板子默认连不上）
接错线 / 没选 SW → 报 No target connected
七步记忆芯片 → 启动 → 库 → 用户 → 宏 → 路径 → 调试器。复制模板时检查这 7 处，基本不会出问题。
3
工程目录分工（点击文件夹展开看内容）
▶📁 Start/启动 + 内核

• startup_stm32f10x_md.s — 启动文件（向量表 + 复位流程）
• core_cm3.h / core_cm3.c — Cortex-M3 内核定义
• system_stm32f10x.c — 系统时钟初始化
一般不用动，复制模板带来即可

▶📁 Library/固件库源码

• stm32f10x_gpio.c/h、stm32f10x_rcc.c/h、stm32f10x_tim.c/h…
• stm32f10x.h — 总头文件（寄存器定义）
• misc.c/h — NVIC 等内核外设
按需添加：用到哪个外设加哪个 .c，全加也行

▶📁 System/公共模块

• Delay.c/h — 软件延时（SysTick）
• Timer.c/h — 定时器封装（可选）
跨工程复用的通用代码放这里

▶📁 Driver/外设驱动（你写的）

• Led.c/h、Key.c/h、OLED.c/h、Servo.c/h、Encoder.c/h…
你的主力工作区：一个外设 = 一对 .c/.h 文件
命名规范：驱动名 + 下划线 + 函数名（Led_Init、Key_GetNum）

▶📁 User/应用层

• main.c — 主程序（初始化 + 主循环）
• stm32f10x_it.c — 中断服务函数
• stm32f10x_conf.h — 库配置（勾选外设模块）
main.c 只负责"指挥"，具体功能在 Driver/System 里

分层思想Start/Library 是"地基"（模板自带），System/Driver 是"组件"（复用），User 是"应用"（每工程不同）。维护习惯比代码本身重要——这也是以后工作的项目规范。
4
两个核心概念（搞懂=入门一半）

① 固件库两层封装

// 寄存器层：直接操作寄存器（快，但繁琐、可读性差）
GPIOA->ODR |= 0x0010;

// 库函数层：封装好的函数（底层还是写寄存器，编译器会优化）
GPIO_SetBits(GPIOA, GPIO_Pin_4);
性能两者性能几乎无差别——库函数多是指令内联/宏展开。入门用库函数，看懂库源码（stm32f10x_gpio.c）是进阶关键。

② 工程配置文件 stm32f10x_conf.h

它通过注释/取消注释控制哪些外设库模块被编译（省 Flash 空间）：

#include "stm32f10x_gpio.h"
// #include "stm32f10x_spi.h"   ← 不用 SPI 就注释掉
// #include "stm32f10x_usart.h" ← 用 USART 就取消注释
坑如果把用到的外设头文件在 conf.h 里注释掉，编译会报 identifier is undefined——症状很诡异，其实只是 conf.h 没勾选。
5
即时自测（点选项立刻见对错）
1. 启动文件 startup_stm32f10x_md.s 里的 "md" 代表什么？点击选项
Micro Debug（微型调试模式）
Medium Density，中容量芯片（64~128KB Flash）专用
Multiple Devices（多设备支持）
Main Driver（主驱动文件）
✓ 正确！md = Medium Density。C8T6（64KB Flash）正好是中容量，所以用 startup_stm32f10x_md.s。选错启动文件芯片上电就跑飞。
✗ 不对。md = Medium Density（中容量，64~128KB Flash）。C8T6 是 64KB Flash = 中容量，所以用它。启动文件负责上电初始化（向量表 + 堆栈 + 进 main）。
2. 宏定义 STM32F10X_MD 漏写会发生什么？点击选项
没有任何影响，写不写都行
编译报错：找不到 stm32f10x.h
库函数按"错误容量"配置 Flash 分页等参数，可能导致烧录/擦除异常
程序能编译，但下载一定失败
✓ 正确！STM32F10X_MD 告诉库"芯片是中容量"，影响 Flash 分页大小等参数。选错容量可能导致烧录异常。换芯片必须同步改这个宏（LD/MD/HD/XL）。
✗ 不对。STM32F10X_MD 是"芯片容量开关"，影响 Flash 分页等参数配置。漏写或写错 → 库按错误容量配置 → 烧录/擦除可能异常。换芯片必须同步改（LD/MD/HD/XL）。
3. #include "Led.h" 报 cannot open source input file，第一反应查什么？点击选项
Led.h 文件内容写错了
Include Paths 里有没有 Led.h 所在目录（如 .\Driver）
Keil 没注册，需要重新激活
芯片型号选错了
✓ 正确！编译器按 Include Paths 的目录清单找 .h 文件。目录里没有 → 报 cannot open。加路径 or 确认文件名大小写/拼写。这是 1002 踩过的坑。
✗ 不对。报 cannot open 说明编译器找不到文件。第一反应查：① Include Paths 是否包含 Led.h 所在目录；② 文件名拼写/大小写。文件内容错误会报别的错（如语法错误）。
4. 库函数（GPIO_SetBits）和寄存器操作（GPIOA->ODR），性能哪个快？点击选项
库函数慢很多，因为多了函数调用开销
寄存器操作一定更快
差不多，库函数多为内联/宏，编译器会优化成等价的寄存器操作
库函数快，因为固件库做了优化
✓ 正确！库函数底层就是操作寄存器，多为内联/宏实现，编译器优化后与直接写寄存器等价。性能差距可忽略，入门用库函数可读性更好。
✗ 不对。两者性能几乎无差别——库函数封装的是寄存器操作，内联/宏展开后编译器会优化成等价指令。入门用库函数（可读性），进阶直接操作寄存器（更精细控制）。
5. Keil 配置调试器时，Port 为什么选 SW 而不是 JTAG？点击选项
SW 下载速度比 JTAG 快 10 倍
SW（SWD）只要 2 根信号线，省引脚；ST-Link 和板子都支持，默认用它
JTAG 已经停产，Keil 不推荐
SW 不需要共地
✓ 正确！SWD 只需 SWDIO+SWCLK 两根信号线，比 JTAG（5 线）省引脚。你的板子和 ST-Link 都走 SWD，所以选 SW。选错/接错 → No target connected。
✗ 不对。选 SW 是因为 SWD 只需 2 根信号线（SWDIO=PA13、SWCLK=PA14），比 JTAG 的 5 根线省引脚，且板子/ST-Link 都默认支持。下载速度不是主要考虑。
